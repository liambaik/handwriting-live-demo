# 실시간 손글씨 인식 데모 (handwriting-live-demo)

카메라 화면 가운데 **가이드 박스**에 종이 손글씨를 비추면, 글자를 한 글자씩 잘라 CNN으로 읽고 화면에 바로 띄웁니다.

- 읽을 수 있는 글자는 **숫자 0~9와 대문자 A~Z (36자)**입니다. 소문자, 하이픈(-), 한글은 읽지 못합니다.
- 다른 프로젝트(`marking-recovery`, `welding-exposure-control`)와 독립된 폴더입니다. 다른 프로젝트 코드는 import하지 않고, 학습된 모델 파일(`models/cnn_ocr36.pt`)만 복사해 왔습니다.

## 1. 설치 (처음 한 번)

**Python 3.9 이상**이 필요합니다. macOS 기본 Python 3.9에서도 동작합니다. 3.9에서는 torch 2.8이 설치됩니다.

| | macOS / Linux | Windows |
|---|---|---|
| 설치 | `./setup.sh` | `setup.bat` |
| 손글씨 판별 화면 | `./run_check.sh` | `run_check.bat` |
| 글자 읽기 화면 | `./run.sh` | `run.bat` |
| 사진 모으기 / 재학습 | `./run_collect.sh` / `./run_train.sh` | `run_collect.bat` / `run_train.bat` |

- `setup.sh`는 설치된 Python 중 가장 새 버전(3.13 → 3.9 순)을 자동으로 고릅니다. 직접 정하려면 `PYTHON=/경로/python3 ./setup.sh`로 실행합니다.
- 검증한 버전은 `requirements-lock.txt`에 있습니다 (Python 3.12, torch 2.14.1). Python 3.9 + torch 2.8.0에서도 테스트 11개가 통과했습니다.

### 다른 컴퓨터에서 실행하기

```bash
git clone https://github.com/liambaik/handwriting-live-demo.git
cd handwriting-live-demo
./setup.sh                      # Windows: setup.bat
./run.sh --list-cameras         # 카메라 번호 확인 (Windows: run.bat --list-cameras)
./run_check.sh --device 번호    # Windows: run_check.bat --device 번호
```

- **카메라 번호는 컴퓨터마다 다릅니다.** 기본값 `--device 0`은 이 프로젝트를 만든 Mac에서 iPhone이었던 번호입니다. 다른 컴퓨터에서는 `--list-cameras`로 확인한 번호를 넣으세요. 노트북 내장 카메라만 있으면 보통 0입니다.
- **macOS 카메라 권한:** **시스템 설정 > 개인정보 보호 및 보안 > 카메라**에서 터미널(또는 VS Code)을 켜고, 그 앱을 완전히 종료(⌘Q)했다가 다시 엽니다.
- **회전 보정은 하지 않습니다.** 카메라를 돌리는 대로 화면도 그대로 돌아갑니다. 화면을 직접 돌리고 싶으면 `r`을 누르세요. 누를 때마다 시계 방향으로 **30°씩** 돌아가고, 각도는 저장되지 않아 다시 켜면 0°입니다.
- **판정 가중치:** 모델과 가중치 파일(`models/`)은 저장소에 포함되어 있어 따로 받을 필요가 없습니다. iPhone으로 다시 학습한 가중치(`model_parameters_iphone.json`)가 자동으로 쓰입니다.
- 학습에 쓴 iPhone 사진(`data/`)은 저장소에 없습니다. 그 컴퓨터에서 다시 학습하려면 `run_collect`로 사진부터 모아야 합니다.

## 2. 실행

```bash
./run.sh --list-cameras      # 1) 카메라 번호 확인 (iPhone은 화면이 켜져 있어야 함)
./run.sh --device 1          # 2) 그 번호로 실행
./run.sh --image 사진.jpg    # 카메라 없이 사진 한 장 읽기
```

> **macOS 카메라 권한**: `카메라를 열 수 없습니다`가 나오면 **시스템 설정 > 개인정보 보호 및 보안 > 카메라**에서
> VS Code(또는 터미널)를 켭니다. 그다음 그 앱을 **완전히 종료(⌘Q)했다가 다시 여세요.**
>
> macOS는 카메라 번호(0, 1)를 실행할 때마다 바꾸기도 합니다. 화면이 검게 나오면 `--list-cameras`로 다시 확인하세요.

### 잘 읽히게 쓰는 법

- **숫자와 대문자만, 또박또박, 글자 사이를 띄워서** 씁니다. 붙여 쓰면 두 글자가 한 조각으로 잘려 틀리기 쉽습니다.
- **굵은 펜**(네임펜, 보드마커)이 볼펜보다 잘 읽힙니다.
- 종이를 가이드 박스 안에 꽉 차지 않게 두고, **종이 끝이나 손가락이 박스 테두리에 닿지 않게** 합니다.
- **한 글자 높이가 화면의 1/10 이상**이 되도록 가까이 비춥니다.
- 확신도에 따라 박스 색이 바뀝니다.
  - 초록: 0.8 이상
  - 노랑: 0.5 이상
  - 빨강: 0.5 미만, 글자 대신 `?`로 표시
- 위 패널의 `Read`는 지금 프레임에서 읽은 결과입니다. `Stable`은 최근 10프레임 중 5번 이상 같게 나온 결과입니다.

### 단축키

| 키 | 동작 |
|---|---|
| `q` / `ESC` | 종료 |
| `space` | 화면 멈춤/재개 |
| `s` | 현재 결과 저장 (`captures/날짜_시간/`: 원본, 결과 화면, 글자 이미지, result.json) |
| `d` | 디버그 보기: 잉크 마스크와, 모델에 실제로 들어가는 글자 이미지 |
| `p` | 글씨 색 판단: `auto` → `dark`(흰 종이에 어두운 글씨) → `light`(어두운 바탕에 밝은 글씨) |
| `[` / `]` | 민감도 낮춤 / 높임. 흐린 글씨가 안 잡히면 `]`, 종이 결이나 잡음이 잡히면 `[` |

### 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--device` | 0 | 카메라 번호 |
| `--roi W H` | 0.7 0.5 | 가이드 박스 크기 (화면 대비 비율) |
| `--polarity` | auto | auto / dark / light |
| `--sensitivity` | 12 | 주변보다 이만큼 진해야 잉크로 봄 (작을수록 민감) |
| `--min-conf` | 0.5 | 이보다 확신도가 낮으면 `?` |
| `--image` | | 카메라 대신 사진 파일 |

## 3. 동작 방식

```
카메라 ─▶ 가이드 박스 자르기 ─▶ 글씨 밝게(종이 글씨 반전) ─▶ 잉크 찾기 ─▶ 글자·줄 나누기 ─▶ 한 글자씩 정규화 ─▶ CNN ─▶ 화면 표시
```

1. **글씨 색 맞추기**: 모델은 "회색 바탕에 밝은 글씨"로 학습했습니다. 종이 손글씨(흰 바탕, 어두운 글씨)는 밝기를 반전합니다.
2. **잉크 찾기**: 주변보다 확실히 진한 픽셀을 잉크로 봅니다. 주변 밝기와 비교하기 때문에 조명이 한쪽으로 기울어도 동작합니다.
3. **정리**: 작은 점, 가이드 박스 테두리에 닿은 덩어리(종이 끝, 그림자), 줄 노트의 긴 선은 지웁니다.
4. **글자·줄 나누기**: 가로로 겹치고 세로로 가까운 조각은 한 글자로 묶습니다(끊긴 획). 세로 위치로 줄을 나누고, 줄 안에서는 왼쪽부터 읽습니다.
5. **글자 이미지**: 각 글자에서 **그 글자의 잉크만 남기고 옆 글자 조각은 지웁니다.** 이전 평가에서 옆 글자 조각이 섞여 A를 H로 읽는 오류가 있어서 넣은 처리입니다. 그다음 학습 때와 똑같이 128px로 정규화하고 64px로 줄여 모델에 넣습니다.
6. **모델** ([recognizer.py](hw_demo/recognizer.py)): ResNet18, EMNIST 손글씨 숫자와 대문자 36종으로 학습했습니다. EMNIST test 정확도는 92.5%입니다.

## 4. 검증 결과

| 확인 | 결과 |
|---|---|
| 테스트 (`.venv/bin/python -m pytest -q`) | 5개 통과: 반전, 글자·줄 순서, 옆 글자 조각 제거, 잡음·테두리 무시, 모델 로드 |
| 흰 종이 합성 사진 40장 (EMNIST test 글자 6자 × 2줄, 조명 기울기 + 잡음) | 글자 수를 맞게 자른 줄 79/80, 글자 정확도 93.7% |

합성 사진의 글자 정확도가 EMNIST test 정확도(92.5%)와 비슷합니다. 따라서 종이 글씨를 반전하고 정규화하는 과정이 학습 형식과 잘 맞습니다. 실제 카메라에서는 초점, 흔들림, 그림자 때문에 이보다 낮을 수 있습니다.

## 5. 한계

- **36자만 읽습니다.** 소문자를 쓰면 가장 비슷한 대문자나 숫자로 읽습니다.
- **헷갈리기 쉬운 글자 쌍**이 있습니다: O/0, I/1/L, 2/Z, 5/S. 손으로 쓰면 원래 모양이 거의 같습니다. EMNIST test에서도 가장 많이 틀린 쌍입니다.
- **붙여 쓴 글자는 한 조각이 되어 틀립니다.** 글자 사이를 띄워 주세요.
- **맞춤법 같은 문맥 보정은 없습니다.** 글자를 하나씩 따로 읽습니다.

# 손글씨 판별 화면 (check.py): 손글씨면 `1`, 아니면 아무것도 표시하지 않음

글자를 읽지 않고, 가이드 박스 안이 **손글씨인지만** 판단합니다.
판단에는 `models/model_parameters.json`(Downloads에서 복사)의 로지스틱 회귀를 그대로 씁니다. 특징 8개, 평균·표준편차, 가중치, bias 7.48, 기준 0.5가 들어 있습니다.

```bash
./run_check.sh                 # iPhone 카메라 (기본 --device 0)
./run_check.sh --device 1      # Mac 내장 웹캠
```

> 이 Mac 에서 확인한 번호: **0 = iPhone**(최대 1920×1080), **1 = 내장 웹캠**(정사각형 1552×1552 지원).
> macOS 는 OpenCV 카메라 번호 순서가 기기 목록과 다를 수 있어, 해상도로 구분했습니다.

```bash
./run_check.sh --image a.png   # 사진 한 장: 손글씨면 1 출력, 아니면 빈 줄
```

- 화면 가운데 얇은 회색 박스 안에 종이를 비춥니다.
- 최근 8프레임 중 과반이 손글씨로 판정되면 화면 위쪽에 큰 초록색 `1`이 뜹니다. 아니면 아무것도 뜨지 않습니다.
- 빈 종이나 벽처럼 글씨가 없으면 판정하지 않고 아무것도 띄우지 않습니다.
- **먼저 "종이 위에 쓴 글씨가 있는지"를 확인한 뒤에만 판정합니다.** 이 판정 모델은 "정형 vs 손글씨"만 배웠고 "글씨 없음"은 모릅니다. bias(+7.48)가 커서 얼굴이나 방 같은 장면도 손글씨로 나오기 때문입니다. 확인 순서는 다음과 같습니다.
  1. 밝은 종이보다 확실히 진한 **가는 선**만 잉크로 봅니다. 큰 물체와 그림자는 제외합니다.
     - **색 펜·연필 대응:** 흑백 하나가 아니라 B·G·R 채널마다 종이보다 진한 정도를 재서 가장 큰 값을 씁니다. 흑백에서는 사라지는 노란 펜도 파랑 채널에서는 잡힙니다.
     - 잉크 기준은 고정값이 아니라 화면 잡음의 5배(12~30)로 자동으로 정합니다. 깨끗한 화면에서는 연한 연필도 잡힙니다.
     - 판정 모델에는 잉크 색과 진하기에 상관없이 "흰 바탕 + 진한 글씨"로 맞춘 이미지를 넣습니다.
     - iPhone 손글씨 사진 10장의 잉크를 바꿔 넣은 확인 결과: 검정·파랑·빨강·초록·주황·노랑·진한 연필은 10/10, 연한 연필은 9/10에 `1`이 떴습니다. 바꾸기 전에는 노랑 0/10, 연한 연필 0/10이었습니다.
  2. 박스 테두리에 닿은 선(물체 모서리, 종이 끝, 박스에서 잘린 글씨)은 뺍니다. 이런 선이 나머지 잉크의 2배를 넘으면 글씨가 아닌 것으로 봅니다.
  3. **획 주변이 고른 종이인지** 봅니다. 주변 밝기 표준편차가 15를 넘으면 뺍니다. 실제 종이 사진의 획은 보통 3.7, 얼굴(머리카락, 눈)은 약 30입니다.
  4. 잉크 양, 획 굵기, 획 모양을 확인합니다.
  5. 통과하면 **글씨 부분만 잘라서** 판정합니다.
  - 확인 결과:
    - 얼굴이 비친 카메라 화면: 30프레임 모두 아무것도 안 띄움
    - 종이 손글씨 사진 100장: 81장에 `1` 표시
    - 정형 글자 20장(종이 인쇄처럼 반전): 3장에 잘못 `1` 표시
- 단축키:
  - `d`: 확률과 특징값 보기. 글씨로 인정되지 않으면 `no writing` / `not writing`이 표시됩니다.
  - `s`: 저장 (`captures/check_날짜_시간/`). 박스 안 글씨만 남긴 투명 PNG `cutout.png`도 함께 저장
  - `m`: **전체 화면 2분할** 켜기/끄기 (카메라 | 글씨 누끼)
    - 화면 비율을 보고 좌우와 위아래 중 더 크게 보이는 배치를 고릅니다. 맥북 화면에서는 위아래로 나뉩니다.
    - 카메라 칸은 빈틈없이 채우도록 확대합니다. 가장자리는 조금 잘려도 가이드 박스 영역은 잘리지 않습니다. 손글씨면 칸 오른쪽 위에 `1`이 뜹니다.
    - 누끼 칸은 글씨가 잘리지 않게 최대한 크게 넣고, 남는 곳은 투명(체크무늬)으로 채웁니다.
    - **누끼 글씨는 빨간색**으로 칠합니다. 화면과 저장 PNG 모두 같습니다. 원래 글씨 색으로 보려면 `./run_check.sh --cutout-original-color`로 실행합니다.
    - **손글씨로 판단해 `1`이 떴을 때만** 누끼를 계산합니다. 아니면 가운데에 `no cutout (not handwritten)`을 크게 표시합니다.
  - `s`: **누끼 사진 저장** → `captures/cutout_날짜_시간.png` (투명 배경 PNG, 화면에 보이던 누끼 그대로). 저장되면 화면에 `SAVED`가 뜹니다.
    - `1`이 안 떠 있으면 저장하지 않고 `NO CUTOUT TO SAVE`를 띄웁니다.
    - 판정 기록(원본 화면, 결과 화면, `result.json`)은 `captures/check_날짜_시간/`에 함께 저장됩니다.
  - `q`: 종료

## 판정 공식

```
z_i  = (특징_i - 평균_i) / 표준편차_i          (계산할 수 없는 특징은 JSON 의 중앙값으로 대체)
점수 = 7.4827 + Σ 가중치_i · z_i
확률 = 1 / (1 + e^-점수)        확률 ≥ 0.5 → 손글씨 → 1 표시
```

## 특징 계산 방식 (중요: 원본 코드가 없어 근사함)

JSON에는 평균, 표준편차, 가중치만 있고 **특징을 계산하는 코드는 없습니다.** 그래서 이름에 맞는 계산 방식을 여러 개 만들어 봤습니다. 그중 학습 데이터(`Downloads/formal_handwritten_120_png`, 120장)에서 잰 평균·표준편차가 JSON 값과 가장 가까운 방식을 골랐습니다.

| 특징 | 이 프로젝트의 계산 방식 | JSON 평균/std | 120장 측정 평균/std |
|---|---|---|---|
| ① 획 두께 변화 | 중심선(Zhang-Suen) 위 획 두께의 변동계수 | 0.204 / 0.056 | 0.194 / 0.059 |
| ④ 문자 간격 편차 | 이웃 글자 간격의 변동계수 (2글자 이상) | 0.587 / 0.518 | 0.543 / 0.427 |
| ⑤ 기울기 변화 | 세로 획(±30°) 경계 기울기의 표준편차(도) | 13.41 / 2.41 | 14.55 / 2.64 |
| ⑥ Baseline 흔들림 | 글자 아래끝 높이 (최대−최소) / 글자 높이 | 0.266 / 0.408 | 0.284 / 0.563 |
| ⑧ 곡률 변화 | 외곽선 5px 간격 방향 변화(라디안)의 표준편차 | 0.502 / 0.085 | 0.528 / 0.096 |
| ⑩ 연결요소 크기 분산 | 연결요소 면적의 변동계수 | 0.387 / 0.250 | 0.383 / 0.252 |
| ⑪ 외곽선 불규칙도 | 볼록 껍질 면적 합 / 잉크 면적 | 2.124 / 0.415 | **1.754 / 0.341** (가장 차이 큼) |
| ⑫ 획 연결성 | 1 / 연결요소 수 | 0.365 / 0.127 | 0.332 / 0.130 |

공통 전처리는 다음과 같습니다.
1. 글씨를 밝게 맞춥니다.
2. Otsu로 이진화합니다.
3. 작은 점을 제거합니다.
4. 잉크 영역 높이를 100px로 맞춥니다.

**이 계산 방식으로 120장을 판정한 결과** (JSON 가중치 그대로):

| 정답 | 장수 | 맞게 판정 |
|---|---|---|
| 정형 | 20 | 18 (90%) |
| 손글씨 | 100 | 88 (88%) |

JSON에 적힌 학습 정확도는 99.5%인데, 그보다 낮은 이유는 특징 계산 방식이 원본과 완전히 같지 않기 때문입니다. **원본 특징 추출 코드가 있으면 `hw_demo/hw_features.py`의 `compute_features()`를 그 코드로 바꾸면 됩니다.** 판정 공식과 화면은 그대로 쓸 수 있습니다.

또 이 120장은 정형이 화면 캡처(어두운 바탕, 밝은 글씨)이고 손글씨가 종이 사진입니다. 카메라로 종이에 인쇄된 정형 글자를 비추는 상황과는 다를 수 있습니다.

## iPhone 사진으로 가중치 다시 학습하기

주신 가중치(`model_parameters.json`)는 정형 데이터가 **화면 캡처 20장**뿐이라, 카메라로 찍은 인쇄 글자도 손글씨로 판정하는 경우가 많습니다.

| 가중치 | 카메라 촬영 인쇄 글자에 1이 잘못 뜨는 비율 |
|---|---|
| 원래 가중치 (합성 실험) | 약 37% |
| 같은 특징 8개로 다시 학습 (합성 실험) | 약 8% |

그래서 iPhone으로 직접 찍은 사진으로 다시 학습할 수 있게 해 두었습니다.

```bash
./run_collect.sh      # 1) 사진 모으기: 손글씨를 비추고 h, 인쇄 글자를 비추고 p (각 10장 이상, 30장 이상 권장)
./run_train.sh        # 2) 다시 학습 → models/model_parameters_iphone.json (원래 JSON 은 그대로)
./run_check.sh        # 3) 판별 화면: 새 가중치 파일이 있으면 자동으로 사용
```

- **학습 방식:** 원래 JSON과 같습니다. 특징 8개, 로지스틱 회귀, 균형 BCE + L2를 쓰고, 10회 반복 5-fold 교차검증으로 λ를 고릅니다. 학습 결과 파일도 원래 JSON과 같은 형식입니다.
- **원래 데이터 함께 쓰기:** 원래 120장도 같이 쓰려면 `./run_train.sh --with-original`을 실행합니다.
- **원래 가중치로 되돌리기:** `./run_check.sh --params models/model_parameters.json`
- **사진 저장 위치:** 모은 사진은 `data/iphone/handwritten/`, `data/iphone/printed/`에 저장되고 git에서는 제외됩니다.
- **잘 모으는 법:**
  - 글자 내용, 펜 색, 크기, 거리, 각도, 조명을 바꿔 가며 찍습니다.
  - 인쇄 글자는 실제로 구분해야 할 대상(마킹, 라벨, 인쇄물)과 비슷한 것을 찍습니다.
  - 박스 테두리가 초록색(글씨 확인 통과)일 때 저장해야 학습에 쓰입니다.

## 글씨 누끼 (hw_demo/cutout.py)

> **누끼는 손글씨로 판단해 `1`이 떴을 때만 실행합니다.**
>
> - 실시간 화면(`m` 2분할): `1`이 안 떠 있으면 누끼를 계산하지 않고, 오른쪽에 `no cutout (not handwritten)`만 크게 보입니다.
> - `s` 저장: `1`이 떠 있을 때만 `cutout.png`를 저장하고, 아니면 `result.json`의 `cutout`에 "안 함"이라고 남깁니다.
> - 사진 모드 `--image ... --cutout 결과.png`: 손글씨로 판단될 때만 PNG를 저장합니다.

종이·바탕은 투명하게 하고 **글씨 획만 원래 색으로 남긴** PNG를 만듭니다. `hoonibbong` 브랜치 `PAC2/src/pac2/extraction.py`의
획 단위 후보 마스크 방식을 이 데모(OpenCV·numpy만 사용)에 맞게 옮긴 것입니다.

```bash
./run_check.sh                                    # 화면에서 m: 미리보기, s: cutout.png 저장 (Windows: run_check.bat)
./run_check.sh --image a.png --cutout a_cut.png   # 사진 한 장 → 투명 PNG
```

- **방식:** 중앙값에서 가장 벗어난 쪽으로 잉크 극성을 정하고, 커널 9·15·25·41px 모폴로지 hat 응답의 최댓값을 잡음 기준
  `max(10, 중앙값 + 5×1.4826×MAD)`로 이진화합니다. 커널보다 굵은 얼룩·조명은 반응하지 않습니다. 컬러 영상은 B·G·R 채널별로 재서
  노란 펜도 잡힙니다.
- **표면 요철·흐린 얼룩 제거:** 임계값을 잡음 기준 하나로만 두면 철판 표면의 요철·산화 얼룩도 획으로 잡힙니다. 그래서 '확실한 잉크'
  (잡음 위 응답의 상위 98%)를 기준으로 상대 조건을 둡니다. 픽셀은 그 40% 이상(`rel_thr`)이어야 하고, 성분은 응답 상위 10%가
  그 60% 이상(`core_frac`)이어야 유지합니다. 진한 펜 글씨는 남고 대비가 약한 얼룩은 덩어리째 빠집니다.
  글씨가 연할수록 같이 빠질 수 있으니, 흐린 글씨가 잘리면 두 값을 낮추고(예: 0.35/0.5) 요철이 따라오면 높이세요(예: 0.5/0.7).
- **손가락(피부색) 제외:** 컬러 영상에서 YCrCb 피부색 범위를 찾아 큰 열기(15px)로 가는 획을 지우고, 화면의 2% 미만인 작은 조각은 버린 뒤
  가장자리 9px까지 넓혀 '손 영역'으로 씁니다. 성분의 절반 이상이 이 영역 안이면 제외합니다(손가락 그림자 선·마디 주름이 획으로 잡히던 문제).
  붉은 펜 글씨는 색이 살색 범위에 걸려도 면적이 작아 손으로 취급되지 않습니다. 끄려면 `CutoutConfig(drop_skin=False)`.
- **거르기:** 12px 미만 점, 두께/긴 변 > 0.35인 덩어리, (가이드 박스 테두리에 닿은 성분), 화면 변의 40%를 넘는 긴 선을 뺍니다.
- **수기만 남기기 (기본):** 획을 근접 묶음(글자·단어 단위)으로 묶고, 묶음마다 이 데모의 손글씨 판별기(`HandwritingClassifier`)로
  판정해 손글씨로 판정된 묶음의 획만 남깁니다. 인쇄 글자는 빠집니다. 인쇄 글자까지 포함하려면 `--cutout-all`, 화면에서는 `a` 키로 전환합니다.
  기준 확률은 `--hw-threshold`(기본 0.4)로 조절합니다. 낮추면 수기를 덜 놓치고 인쇄가 섞이며, 높이면 반대입니다.
- **PAC2와 다른 점:** PAC2는 묶음 판정에 자체 학습한 체크포인트(scikit-learn)를 쓰지만 `hoonibbong` 브랜치에 모델 파일이 없어, 이 데모에 이미 있는 판별기로 대체했습니다.
- **한계:** 판별기는 종이 손글씨 사진으로 학습한 가중치라, 철판 위 마킹에서는 수기를 놓치거나(재현율) 긁힘 선이 따라올 수 있습니다.
  철판 수기 사진이 모이면 `run_collect`/`run_train`으로 다시 학습하세요. 글자가 한두 개뿐인 묶음은 간격·기준선 특징을 못 구해 판정이 불안정합니다.
- 누끼 계산은 한 번에 0.2~0.3초가 걸려서 **별도 스레드**(`LatestWorker`)에서 돌립니다. 카메라 화면은 계속 부드럽게 갱신되고, 누끼 창은 계산이 끝나는 대로
  가장 최근 프레임 기준으로 갱신됩니다(초당 3~5회, 실제 움직임보다 조금 늦게 따라옴). 계산은 `m`을 켰을 때만 합니다.
- 흐린 글씨가 끊기거나 종이 결이 따라오면 `hw_demo/cutout.py`의 `CutoutConfig.noise_k`(기본 5)를 조절하세요.
